## Findings

### F1 — Preview U/R not wired in Phase 3 data contract

- **Severity**: ⚠️ WARNING
- **Impact**: 🔬 HIGH — architectural stakes; think carefully before deciding
- **Dimension**: End-State Alignment
- **Location**: Desired End State §3; Phase 3 §2 Assembly services; Phase 4 §2 Assembly island
- **Detail**: End state and Phase 4 require **server-computed** R_total/U on the assembly list after reload. Phase 2 defines `computeAssemblyPreview`, but Phase 3 `listAssembliesWithLayers` does not specify attaching `rTotal`/`uValue` per assembly. An implementer could finish Phase 3–4 with layers persisted but no preview in the UI while manual criteria still “pass” if they skip checking preview.
- **Fix A ⭐ Recommended**: Extend Phase 3 `assemblies.ts` contract: `listAssembliesWithLayers` (and create/update return path if needed) maps layers through `computeAssemblyPreview` and returns `{ ...assembly, preview: { rTotal, uValue } }`.
  - Strength: Single server source of truth; matches “preview not persisted” decision.
  - Tradeoff: Recompute on every page load (acceptable per Performance section).
  - Confidence: HIGH — aligns with Phase 2 module and Desired End State.
  - Blind spot: None significant.
- **Fix B**: Compute preview only in `[id].astro` frontmatter after fetch
  - Strength: Keeps service layer thinner.
  - Tradeoff: Duplicates preview invocation at page layer; island and SSR could drift.
  - Confidence: MEDIUM — works but weaker boundary.
  - Blind spot: Island edit flows might omit preview if not passed props consistently.
- **Decision**: FIXED via Fix A

### F2 — Layer payload encoding left as “pick one”

- **Severity**: ⚠️ WARNING
- **Impact**: 🔎 MEDIUM — real tradeoff; pause to reason through it
- **Dimension**: Plan Completeness
- **Location**: Phase 3 §4 Assembly APIs
- **Detail**: Contract says `layers[0].lambda` **or** JSON in hidden field — not chosen. React island + form POST needs a fixed shape before Phase 4; mismatch breaks Zod parsing.
- **Fix A ⭐ Recommended**: Standardize on indexed form fields (`layers[0][material_name]`, etc.) generated by the island on submit — mirrors `formData` + Zod `z.preprocess` from array-like keys; no JSON in hidden fields.
  - Strength: Consistent with S-01 `form.get("name")` pattern; debuggable in Network tab.
  - Tradeoff: Verbose field names; cap layer count in UI (already capped in Zod).
  - Confidence: HIGH — matches `CreateProjectDialog` HTML form approach.
  - Blind spot: Astro/React form field naming must match Zod schema exactly.
- **Fix B**: Single hidden `layers` JSON string field
  - Strength: Compact forms for many layers.
  - Tradeoff: Extra parse step; easier to bypass client validation; less consistent with existing APIs.
  - Confidence: MED.
  - Blind spot: XSS/escaping less of an issue for POST to own API but parsing errors are harsher UX.
- **Decision**: FIXED via Fix A

### F5 — Layer replace on update is not transactional

- **Severity**: ⚠️ WARNING
- **Impact**: 🔎 MEDIUM — real tradeoff; pause to reason through it
- **Dimension**: Blind Spots
- **Location**: Phase 3 §2 Assembly services
- **Detail**: Plan says “replace layers on update” via Supabase client without a DB transaction. Delete-all-then-insert can leave an assembly with **zero layers** if insert fails mid-flight — violates FR-005 spirit and breaks preview (division by zero risk in U calc).
- **Fix A ⭐ Recommended**: Document in Phase 3 contract: **insert new layers first, then delete old** (by id list) on update, or use a Postgres RPC in migration for atomic replace (heavier).
  - Strength: Insert-first avoids empty assembly on insert failure if old rows remain until success.
  - Tradeoff: Brief duplicate order window; needs careful ordering or RPC for cleanliness.
  - Confidence: MED — insert-first is common MVP mitigation without RPC.
  - Blind spot: RPC path not sized in plan.
- **Fix B**: Add `replace_assembly_layers` SQL function in Phase 1 migration (transactional)
  - Strength: True atomicity.
  - Tradeoff: More migration scope; departs from “thin services” pattern.
  - Confidence: HIGH for correctness.
  - Blind spot: Supabase RPC + RLS testing effort.
- **Decision**: FIXED via Fix A
